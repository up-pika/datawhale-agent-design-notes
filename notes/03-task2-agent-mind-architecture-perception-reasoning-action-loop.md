# Task 2 · Agent 心智架构：感知-推理-行动循环

> **材料**：DataWhale 共学 · 黄佳《Agent 设计模式》**第 3 章 3.2 ～ 3.2.5**（配图 3-7～3-14）。  
> **目标**：把“感知—推理—行动”的闭环讲清楚，并整理成可复习、可迁移到工程实践的笔记。

---

## 0. 这节在解决什么问题

传统软件更像流水线：**输入 → 处理 → 输出**，一轮结束就停；而 Agent 要在动态环境里持续适应，所以必须用 **Loop（循环）** 的视角来理解。

- **Agent 不是一次性函数**：更像一个“持续运行的进程”（`while alive`），在环境里反复观察、判断、行动、校验、修正。  
- **核心不是三个独立模块**：感知、推理、行动会互相“咬合”，靠反馈让下一轮变得更准。

---

## 1. 心智架构总览：感知—推理—行动闭环（图 3-7）

可以把 Agent 的工作方式抽象成一个最小闭环：

- **感知（Perception）**：把外部世界（人类输入、环境、工具返回）映射成“当前上下文”。  
- **推理（Reasoning）**：在上下文里做拆解、判断、选择（含权衡与不确定性管理）。  
- **行动（Action）**：调用工具、修改环境、产出可验证的变化。  
- **反馈（Feedback）**：行动改变了世界，世界又反过来改变下一轮感知；推理据此修正计划。

一句话：**让输出不只是回答，而是对世界造成可观测的变化，并用变化校验自己。**

---

## 2. 感知：主动的过滤器（3.2.1）

传统程序“接收输入”；Agent 的感知更像“主动选择”，核心是：**别试图处理所有信息**，要先决定“什么值得看”。

### 2.1 注意力：把噪声挡在门外

- 感知的第一道门是 **Attention**：把有限注意力聚焦到与目标相关的信息上。  
- 多模态场景下，注意力不仅是文本筛选，也包括视觉、结构、历史上下文的聚焦。  
- 工程类类比：  
  - 在网页/文档里忽略无关导航与样式噪声，只盯正文与关键数据；  
  - 在检索里不把整库全塞进上下文，而是先过滤再精读。

### 2.2 预测：靠“偏差”发现新信息

感知不是被动记录，而是基于历史对话、用户偏好、任务背景形成一个“预期”；当现实与预期不一致，会产生“惊奇点”，提醒：**这里可能有新约束/新问题/新价值**。

### 2.3 语义化：从特征到意义

感知的目标不是“识别”，而是“理解”：

- 不只是看见“老人/文件/数字”，还要判断“这意味着什么、与任务有什么关系”。  
- 感知最终服务于行动：把输入转成可用于决策的语义单位，而不是一堆原始信号。

---

## 3. 推理：快思考与慢思考（3.2.2）

课件借用“系统 1 / 系统 2”来解释推理的双模态：

- **System 1（直觉/快）**：快速生成答案，适合闲聊、简单问题与低风险决策。  
- **System 2（分析/慢）**：生成推理链、反思与验证，适合复杂任务、数学/代码/调试等需要可靠性的场景。

推理层通常包含 4 个关键成分：

### 3.1 情境理解（Situation Awareness）

推理先回答：“**现在到底发生了什么？**”  
把当前感知信息与长期记忆、短期上下文整合成一幅清晰的“任务场景图”。

### 3.2 记忆检索（Memory Retrieval）

问自己：“**我是不是见过类似情况？**”  
检索过去的经验（错误模式、已知约束、历史决策）来减少走弯路。

### 3.3 心智模拟（Mental Simulation）

在脑海里预演：“**如果我这样做，会发生什么？**”  
包括：调用某个 API 的后果、读写文件的风险、执行命令是否会破坏环境等。推理不只为了“逻辑正确”，也为了“行动可控”。

### 3.4 决策与信心（Decision & Confidence）

推理要做权衡：哪条路径更贴近目标、更安全、更省成本；同时给出“为什么选它”的依据。  
很多时候，推理的产物不是“答案”，而是“**决策**”。

---

## 4. 行动：改变与反馈（3.2.3）

在传统软件里，`print/return` 常被当作结果；在 Agent 里，**行动是新的开始**：它要对环境产生影响，并把影响当成下一轮推理的证据。

### 4.1 行动让系统进入“行动—反馈环”

- 脚本式执行：执行命令 → 结束。  
- Agent 式执行：执行命令 → 观察结果 → 若不符合预期则调整参数/策略 → 再试。

### 4.2 三种行动的维度

1. **探索性行动：用行动做实验**  
当不确定很高时，行动本身就是获取信息的方式：先小步试探，再根据返回修正理解。

2. **目的性行动：副作用是必需品**  
Agent 的价值来自“能动手”：写库、发邮件、部署代码……这些都带副作用，所以要把副作用纳入世界模型校验：  
“做之前世界什么样？做之后应变成什么样？”

3. **闭环行动：执行—验证—纠偏**  
不鼓励“发射后不管”，而是每次行动都要带一个明确的期望与验证点：
期望 → 执行 → 验证 → 纠偏（定位问题、修复、重试）。

---

## 5. 循环的动力学：OODA 的软件化（3.2.4）

这节的重点是：**智能不是某个模块更强，而是循环跑得更顺、更稳**。

### 5.1 OODA 四步

- **Observe（观察）**：从环境获取上下文。  
- **Orient（定位/整合记忆）**：结合记忆与既有认知，理解局势。  
- **Decide（决策）**：制定行动计划。  
- **Act（行动）**：执行决策、调用工具。  
- **Loop**：行动改变环境，触发新一轮观察。

课件强调关键在 **Orient**：每次循环不仅是做任务，也是在更新自己的“世界模型”。

### 5.2 反幻觉：用现实摩擦做校验

LLM 容易在纯文本里“自洽地编故事”。让 Agent 动起来，真实世界（或真实系统状态）就会给出摩擦与反馈：  
错了就撞墙，撞墙就修正；循环越快、反馈越及时，幻觉越难持续。

### 5.3 时间连续性：循环会生成“历史”

传统程序每次运行像“第一次”；Agent 通过循环累积经验，逐渐把行为从生硬执行变成更像“持续适应”。

---

## 6. 具身认知：身体塑造心智（3.2.5）

感知—推理—行动闭环并不漂浮在真空里，它需要一个“身体”（载体），而身体的限制会反过来塑造智能的形态。

### 6.1 机器人具身：物理约束

- **能量**：推理与行动都要消耗电/算力。  
- **传感器**：视角有限，看不到就得移动/探索。  
- **执行器**：动作有失败概率，需要反馈控制与纠错。

### 6.2 数字具身：数字约束

对运行在服务器上的 Agent，“身体”主要由这些限制组成：

- **上下文窗口**：看不下无限历史，需要“遗忘/巩固/聚焦”。  
- **推理延迟**：深思需要时间，交互场景更敏感。  
- **Token 成本**：每次调用都在消耗预算，逼迫系统学会“省着用”：能检索就别长推理，能小模型就别大模型。

### 6.3 具身性的哲学意义（课件的落点）

限制不是敌人，很多时候反而是创造力与效率的来源：  
它迫使 Agent 学会压缩信息、选择性关注、在有限资源里做更好的决策。

---

## 7. 复习速记（把这一节背下来就够用）

- Agent = **循环中的进程**，不是一次性函数。  
- 感知 = **主动过滤**（注意力/预测/语义化）。  
- 推理 = **快与慢的切换**（情境理解+记忆检索+心智模拟+决策与信心）。  
- 行动 = **改变世界并用反馈校验**（执行-验证-纠偏）。  
- OODA = 循环的骨架，关键在 **Orient：更新世界模型**。  
- 具身 = 约束决定智能形态（窗口、延迟、成本、执行边界）。

---

## 8. 总结（无 AI 感版本）

这一讲把 Agent 拉回到一个很朴素的事实：它不是“会聊天的函数”，而是一套持续运转的闭环系统。它先从环境里抓到有用的线索（感知），把线索放进一个能解释当前局势的框架里（推理），再用工具去改变现实并验证自己是不是判断对了（行动）。真正让它变聪明的不是某一次回答有多精彩，而是它能不能把每一次行动的结果接回来，修正下一轮的理解与选择。  
因此，设计 Agent 的关键也跟写普通程序不太一样：你得关心它看了什么、漏了什么，何时该快、何时该慢，做事之前有没有想清副作用，做完之后有没有对照预期做验证。循环跑得顺，反馈接得住，世界模型才会越更新越靠谱；反过来，如果没有行动与校验，模型就很容易在自圆其说里越走越远。最后别忘了，Agent 的“身体”——上下文窗口、延迟、成本、工具权限——不是外部条件，而是它能力边界的一部分，很多取舍都是被这些约束逼出来的。
